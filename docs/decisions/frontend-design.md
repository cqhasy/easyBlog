# 前端界面设计决策

## 状态

- 状态：已确认
- 日期：2026-09-01
- 适用范围：首版桌面端前端

## 设计目标

easyBlog 的核心价值是便捷地把内容发布到 GitHub 博客。界面应围绕“发现变更、确认内容、完成发布”组织，而不是把写作编辑作为主要工作区。

产品面向个人作者，首版只优化桌面端，不实现移动端布局。

## 继承自 PRD 的产品约束

以下行为由 [PRD](../PRD.md) 和相关专题文档定义，前端只负责清晰呈现和编排：

- 内容源支持本地目录、飞书文档和飞书知识库。
- 内容源单向发布到 GitHub，GitHub 不反向写回。
- 检测与发布分离；默认每 30 分钟检测，也支持手动检测。
- 变更包含新增、更新、删除、移动和冲突；删除必须用户确认。
- 每篇文章只能绑定一个来源；重复来源、slug 冲突和目标端外部修改阻止对应发布。
- 发布支持拆分批次，并包含预览、stage、commit、push、失败重试和历史回滚。
- 凭证由系统安全存储管理，日志不得包含正文或凭证。

## 本次确认的界面决策

### 应用框架

- 使用左侧固定导航，入口顺序为：工作台、来源、变更、发布、历史、设置。
- 工作台是默认落点，启动后优先呈现当前可发布状态。
- 首次使用采用三步 onboarding：连接来源、配置 GitHub 目标、完成首次检测。

### 工作台与变更

- 工作台以待发布变更列表为主，来源状态和发布摘要为辅助信息。
- 变更默认按类型分组：新增、更新、删除、冲突。
- 默认筛选可直接发布项；冲突、警告和其他阻断项保持可见，并在顶部显示摘要。
- 变更条目显示标题、来源、变更类型、更新时间、目标路径、状态、转换警告和预计影响文件数。
- 来源目录树按需展开，用于按来源筛选或选择范围，不常驻占用主工作区。

### 预览与发布

- 选中变更后显示固定底部发布栏，包含已选数量和“预览发布”入口；未选中时收缩为状态条。
- 发布批次支持任意混合选择的文章集合，并提供“全选本次变更”快捷操作。
- 点击条目在右侧详情面板打开预览，列表保持可见。
- 详情面板提供来源内容与目标 Markdown 的左右 diff。
- 删除项单独分组且默认不选中。
- 冲突、slug 冲突、权限错误等阻断项自动剔除出可发布批次，不阻塞无关内容。

### 异步状态与恢复

- 检测、转换、提交、推送等异步过程在页面内按阶段展示状态、耗时、失败项和重试操作。
- 发布失败时优先展示失败阶段及“重试该项/重试全部”；详细日志放在可展开的诊断区域。
- 历史页提供发布记录和 commit 信息；回滚位于单条记录的更多菜单中，不与正常发布并列突出。

### 视觉与桌面体验

- 视觉方向偏 Git 客户端：中性、克制、信息密度适中，使用明确的状态色和 diff 视觉语言。
- 没有待发布变更时，空状态显示最近检测时间和“立即检测”操作。
- 提供命令面板，承载检测、搜索、发布预览和页面切换等高频动作。
- 主题跟随系统，首版提供浅色和深色两套主题。
- 默认使用宽窗口，支持调整大小；关键工作区布局设置合理的最小宽度。
